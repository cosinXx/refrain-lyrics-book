# 输入形态处理（三种方式都要能提取歌名 + 作者）

用户给材料的三种常见形态，核心目标一致：**拿到准确的「歌名 + 歌手/作者」列表**，再走歌词流程。

## 形态一：歌单分享链接（最常见）
- 见 `playlist-sources.md`：跑 `fetch_playlist.py "<链接>" -o songs.json`，或浏览器兜底。
- 输出带 `incomplete` 标记：为 true 必须先浏览器补全，不能带着缺歌继续。

## 形态二：单曲分享链接（用户可能一次丢好几条不同平台的歌）
- 也是 `fetch_playlist.py`：自动识别平台（QQ/网易云脚本支持；酷狗/汽水/酷我提示浏览器）。
- 多条单曲链接逐条解析后合并去重，得到歌曲列表。
- 混合输入（一个歌单链接 + 几个单曲链接）也允许：全部解析后合并。

## 形态三：歌单截图（用户拍/截屏的歌单）
- 歌名+歌手全部来自图片，**必须用视觉逐行读取**，不能凭印象编。
- 流程：
  1. 用户发图 → `Read` 图片（`thumbnail_size` 调大到能看清歌名，必要时放大分区域读）。
  2. 逐行提取「歌名」（通常带序号或歌名标签）和「歌手/作者」（通常小字副行）。
  3. 模糊的行标注「待确认」，整理成 `songs.json`（`[{"name","artist"}]`）。
  4. 截图常截断列表（只显示部分歌），向用户说明"截图只能识别 N 首，歌单完整版请发链接"，数量不足时请用户补链接。
- 常见形态：网易云/QQ音乐/酷狗的歌单列表页截图、汽水音乐"我喜欢的音乐"截图、聊天里转发的歌曲卡片截图。
- 歌手名字有歧义时（如"JJ"、"Tanya"），结合上下文补全为常用中文名（林俊杰、蔡健雅）。

## 通用要求
- 所有输入最终统一成 `songs.json` 数组：`[{"name":"歌名","artist":"歌手"}, ...]`。
- 去重：按「歌名+歌手」合并，同名不同版本保留用户点名的版本。
- 数量核对：截图/链接/页面三者给的数字不一致时，以最完整来源为准并向用户说明。
